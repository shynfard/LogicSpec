# LogicSpec Phase 0 Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the complete Phase 0 deliverable set: normative core DSL v0.1 docs, workspace-model docs, VS Code + AI integration design docs, JSON Schema, salon-platform example workspace, CLAUDE.md/AGENTS.md, and README rewrite.

**Architecture:** Documentation-only. `docs/specification.md` is the normative source of truth for the DSL; `schema/logicspec-0.1.schema.json` mirrors it machine-readably; `examples/salon-platform/` exercises every construct and is validated against the schema. All other docs explain one concept each and defer normative statements to the specification.

**Tech Stack:** Markdown (RFC-2119 style), YAML, JSON Schema draft-07, verification via `python3 -c` with `yaml`/`jsonschema` (fallback: `npx ajv-cli`).

## Global Constraints

- Every LogicSpec document: `logicSpec: "0.1"` first key; `kind:` one of `workspace|module|feature|service|events`.
- IDs kebab-case (`^[a-z][a-z0-9]*(-[a-z0-9]+)*$`); events PascalCase (`^[A-Z][A-Za-z0-9]*$`).
- References use identity, never file paths.
- Step types exactly: `page`, `operation`, `decision`, `publish`, `wait`, `outcome`.
- Root manifest is configuration — no derived state (module lists, counts) ever written into it.
- No executable code. JSON Schema is the only machine-readable artifact.
- Spec source of truth: `docs/superpowers/specs/2026-08-09-logicspec-phase0-design.md`. Copy exact YAML shapes from its §1.
- Example file glob: `*.logic.yaml`; root manifest named `logicspec.yaml`.
- Docs cross-link with relative links; every doc starts with an H1 and a one-paragraph purpose statement.

### Task 3: JSON Schema (`schema/logicspec-0.1.schema.json`)

**Files:**
- Create: `schema/logicspec-0.1.schema.json`

**Interfaces:**
- Consumes: `docs/specification.md` shapes.
- Produces: schema used by example files' `# yaml-language-server: $schema=` headers and Task 4 validation. `$id: https://logicspec.dev/schema/logicspec-0.1.schema.json`.

- [ ] **Step 1: Write schema.** Draft-07. Top level: `required: [logicSpec, kind]`, `logicSpec` const `"0.1"`, then `oneOf` per kind discriminated by `kind` const, each requiring its body key (`workspace`/`module`/`feature`/`service`/`events`). Definitions: `kebabId` pattern `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`; `eventName` pattern `^[A-Z][A-Za-z0-9]*$`; `step` as `oneOf` 6 step types keyed on `type` const with per-type required fields (`page`→`actions` object of kebab→kebab; `operation`→`call` pattern `^[a-z][a-z0-9-]*\.[a-z][a-z0-9-]*$`, optional `on-success`, `on-error`; `decision`→`when` string + `branches`; `publish`→`event` + optional `next`; `wait`→`event`, optional `next`, `timeout`; `outcome`→optional `result` enum `[success, failure, cancelled]`). Feature body: `required: [id, name, start, steps]`; `steps` as `patternProperties` kebab→step. Service body: `required: [id, name, operations]`. Events body: `patternProperties` PascalCase→`{description, payload}`. Workspace: `workspace.id/name` + optional `discovery.include/exclude` string arrays. `additionalProperties: false` on bodies; allow optional `description` everywhere.
- [ ] **Step 2: Verify schema itself is valid JSON**

Run: `python3 -m json.tool schema/logicspec-0.1.schema.json > /dev/null && echo OK`
Expected: `OK`

- [ ] **Step 3: Smoke-validate one inline doc**

Run a one-shot: create scratchpad file with the create-booking feature YAML from specification.md, then
`python3 -c "import yaml,json,jsonschema; jsonschema.validate(yaml.safe_load(open('<scratch>/f.yaml')), json.load(open('schema/logicspec-0.1.schema.json')))" && echo PASS`
Expected: `PASS`. (Fallback: `npx --yes ajv-cli validate -s schema/... -d <converted json>`.)

- [ ] **Step 4: Commit** — `git commit -m "docs: add JSON Schema for LogicSpec 0.1"`
